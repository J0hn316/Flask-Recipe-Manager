# Flask Recipe Manager

A full CRUD recipe manager built with **Python**, **Flask**, **SQLite**, **Jinja templates**, **HTML**, and **CSS**.

This project lets users create, view, edit, and delete recipes. It also supports optional recipe image uploads, safe filename handling, upload validation, unique image filenames, flash messages, server-side validation, and image cleanup when recipes are edited or deleted.

---

## Features

- Add new recipes
- View saved recipes
- Edit existing recipes
- Delete recipes
- Upload optional recipe images
- Replace recipe images during edit
- Delete image files when recipes are deleted
- Delete old image files when images are replaced
- Generate unique uploaded image filenames with UUIDs
- Server-side form validation
- Image file extension validation
- Flash messages for add, edit, delete, and error actions
- SQLite database persistence
- Jinja template inheritance
- GitHub-ready setup with `.gitignore`, `.env.example`, `.gitkeep`, and `requirements.txt`

## Core Data Model

Each recipe stores:

| Field            | Purpose                          |
| ---------------- | -------------------------------- |
| `id`             | Unique recipe ID                 |
| `title`          | Recipe name                      |
| `category`       | Optional recipe category         |
| `prep_time`      | Optional prep time in minutes    |
| `cook_time`      | Optional cook time in minutes    |
| `servings`       | Optional number of servings      |
| `ingredients`    | Required recipe ingredients      |
| `instructions`   | Required cooking instructions    |
| `image_filename` | Optional uploaded image filename |
| `created_at`     | Timestamp generated by SQLite    |

## Flask Routes

| Route                  | Method | Purpose                                                    |
| ---------------------- | ------ | ---------------------------------------------------------- |
| `/`                    | `GET`  | Display add form and saved recipes                         |
| `/`                    | `POST` | Add a new recipe                                           |
| `/recipes/<id>/edit`   | `GET`  | Show the edit form for one recipe                          |
| `/recipes/<id>/edit`   | `POST` | Update an existing recipe and optionally replace its image |
| `/recipes/<id>/delete` | `POST` | Delete a recipe and its uploaded image file                |

## Main App Flow

### Create Recipe

```text
User submits recipe form
        ↓
Flask reads text fields from request.form
        ↓
Flask reads uploaded file from request.files
        ↓
validators.py checks required fields, numbers, and file type
        ↓
If valid, image is saved with a unique filename
        ↓
database.py inserts recipe into SQLite
        ↓
Flask redirects home
        ↓
Success flash message appears
```

### Display Recipes

```text
Flask queries all recipes from SQLite
        ↓
Recipes are passed into index.html
        ↓
Jinja loops over recipe rows
        ↓
Recipe cards render with image or placeholder
```

### Edit Recipe

```text
User clicks Edit
        ↓
Flask loads recipe by ID
        ↓
Edit form is pre-filled with current data
        ↓
User submits changes
        ↓
Validation runs
        ↓
If new image uploaded:
    Save new image
    Delete old image file
    Update database image filename
If no new image uploaded:
    Keep existing image filename
        ↓
Redirect home with success message
```

### Delete Recipe

```text
User clicks Delete
        ↓
Flask loads recipe by ID
        ↓
Associated uploaded image file is deleted if it exists
        ↓
Recipe row is deleted from SQLite
        ↓
Redirect home with success message
```

## Validation Rules

Before saving or updating a recipe, the app validates:

- Recipe title is required
- Ingredients are required
- Instructions are required
- Prep time is optional, but must be `0` or greater if provided
- Cook time is optional, but must be `0` or greater if provided
- Servings is optional, but must be `1` or greater if provided
- Recipe image is optional, but if supplied, it must be one of:
  - PNG
  - JPG
  - JPEG
  - GIF
  - WEBP

Validation logic lives in:

```text
validators.py
```

## Image Upload Handling

Uploaded images are stored in:

```text
static/uploads/recipe_images/
```

The app uses:

- `request.files` to access uploaded files
- `secure_filename()` to sanitize filenames
- `uuid4()` to generate unique filenames
- A whitelist of allowed image extensions
- `Path.unlink()` to delete old image files when needed

---

## Why Unique Filenames Matter

If two uploads originally have the same name:

```text
food.jpg
food.jpg
```

the app does not store both as `food.jpg`.

Instead, it generates UUID-style filenames like:

```text
9f3c2d8a3e5b4a9a9b73d81b2b57f201.jpg
c25a2cb7c62f4ed69e2d487c87a48e5a.jpg
```

This prevents accidental overwrites and avoids shared-file bugs between recipes.

---

## Database State vs Filesystem State

This app manages two kinds of state:

| State Type       | Where it lives                  | What it stores                |
| ---------------- | ------------------------------- | ----------------------------- |
| Database state   | `recipes.db`                    | Recipe row and image filename |
| Filesystem state | `static/uploads/recipe_images/` | Actual uploaded image file    |

The app keeps them synchronized by:

- Saving the image file and storing its filename in SQLite
- Keeping the current image if no replacement is uploaded
- Deleting the old image when a replacement image is uploaded
- Deleting the image file when a recipe is deleted

## Getting Started

### 1. Clone the Repository

```bash
git clone <your-repository-url>
cd flask-recipe-manager
```

### 2. Create a Virtual Environment

```bash
python -m venv .venv
```

### 3. Activate the Virtual Environment

#### Windows PowerShell

```powershell
.venv\Scripts\Activate.ps1
```

#### Git Bash

```bash
source .venv/Scripts/activate
```

#### macOS/Linux

```bash
source .venv/bin/activate
```

### 4. Install Dependencies

```bash
pip install -r requirements.txt
```

### 5. Run the Flask App

```bash
flask --app app run --debug
```

### 6. Open in the Browser

Visit:

```text
http://127.0.0.1:5000
```

## Environment Variables

The app supports a `SECRET_KEY` environment variable for Flask session and flash message support.

An example file is included:

```text
.env.example
```

Example:

```env
SECRET_KEY=replace-with-a-random-secret-key
```

For local learning, the app falls back to a development key if no environment variable is set.

## Upload Folder Strategy

The project ignores actual uploaded image files:

```gitignore
static/uploads/recipe_images/*
```

But keeps the folder in Git using:

```gitignore
!static/uploads/recipe_images/.gitkeep
```

This allows the upload folder structure to exist after cloning the repo while keeping local uploaded files out of version control.

## Security-Minded Practices

This project uses several good backend habits:

- Parameterized SQL queries with `?` placeholders
- Server-side validation instead of trusting only browser validation
- POST requests for destructive actions like delete
- Upload file extension validation
- Safe filenames with `secure_filename()`
- Unique filenames to prevent overwrite collisions
- Local uploads, database, and environment files excluded from Git
- Environment-based secret key support
